## 2. 角度 A：架构 / 纪律 / 可测性

### A-1（P0）包级依赖成环，方案直接不可编译

- **发现**：`packages/channels/package.json` 声明 `@bah/host`，而 `channel:web` 插件需要进 `HOST_PLUGINS`（`packages/host/src/boot/plugins/index.ts`），`verify-plugin-config` 只认这份清单。若按"插件放 channels、清单放 host"实现，就是 `host → channels → host`，`tsc -b` 报 TS6202/引用成环。
- **判断**：这是**方向错**，不是命名问题。渠道适配器是比宿主更低的层（宿主组装渠道），M0 的 `channels → host` 只是骨架期随手写的占位依赖，`src` 里没有一个真实 import。
- **处置**：翻转依赖（v1.1 §3）。`channels` 依赖 `@bah/core`；`host` 依赖 `channels`；`tsconfig` 引用同步。**不回收**。
- **残余风险**：`packages/channels` 若将来需要 `HostPlugin` 类型，也不能反向引用——插件定义留在 host，channels 只出纯函数与适配器。

### A-2（P0）DAG 视图的验收项没有数据源

- **发现**：施工单 13 §2.1 要求 DAG 展示"plan 提案 + 节点携带权限级别 + blocked 可见"，T-WEB-006 也按此验收。但全仓检索 `plan/` 事件为零，`plan`/`todo`/`goal` 明确属施工单 14。照抄规格会写出一段**永不触发**的代码，或用假数据糊过去——两者都是造假。
- **判断**：可以**换数据源、不换验收口径**：`tool/call` 自带 `tier`，`tool/result` 自带 `isError/code`，足以派生"节点 + 权限级别 + 失败下游阻断"。
- **处置**：v1.1 §5.4 改为调用图，登记 R-WEB-D1，写明回收条件（`plan/*` 落地后只换投影、不动视图）。
- **审核意见**：这是本次唯一"降级实现"，必须在答辩材料里主动说明，不能等评委问。

### A-3（P1）"事件直接驱动 DOM"会让状态漂移不可避免

- **发现**：v1.0 写"组件由 seq 事件流驱动增量渲染"，但没有规定**中间表示**。若每个视图各自从事件推导，五个视图就有五份推导逻辑；一旦某条事件被漏处理，只有那一个视图错，且无法用快照测出来。
- **处置**：引入 `WebFrame` 作为唯一中间表示（v1.1 §4），投影器纯函数化，DOM 只做"帧 → 节点"。
- **可测性收益**：T-WEB-007 变成"同一串事件两次投影深度相等"，node 侧即可跑，不需要 jsdom。

### A-4（P1）`EventSource` 自动重连会续错点

- **发现**：浏览器 `EventSource` 重连时**复用原 URL**。若首连是 `?since=0`，断线后自动重连仍是 `?since=0`——服务端会重发全量，客户端要么重复渲染要么靠去重兜底；反过来若首连是 `?since=12`，重连后仍从 12 开始，**中间新增的事件永远补不回来**（`since` 是快照点，不是游标）。
- **处置**：禁用自动重连语义——`onerror` 里 `close()`，按 `maxSeq` 重建 URL，1s 退避上限 10 次（v1.1 §8）。服务端仍然做 `seq > since` 过滤，双保险。

### A-5（P1）审批超时不能由 UI 裁决

- **发现**：v1.0 写"倒计时 = 票据 TTL"，容易被实现成"倒计时归零 → 前端当作拒绝并关窗"。但真正的结论只能由 `ApprovalService` 的超时路径产出（`unavailable` → deny）。前端抢跑会造成"界面说超时，服务端其实还在等"，随后票据被批准，资金动了而界面显示未执行——这是资金类产品最不能出现的一类不一致。
- **处置**：客户端倒计时纯视觉；结论只认 `approval/decided` 帧（v1.1 §5.3）。

### A-6（P1）覆盖率口径：新代码不在强制名单里，容易"假绿"

- **发现**：`scripts/coverage-allowlist.ts` 没有 `channels`。投影层是**判决密集**代码（金额降级、三态、阻断传播），按现有纪律应当 100%。
- **判断**：本次扩容名单会牵动 `pnpm test:coverage` 阈值，且 `apps/web` 是 JS 不在 v8 include 面内。强行扩容会把"前端交付"变成"覆盖率治理"。
- **处置**：本次**不扩容**名单，但把 T-WEB-001/005/007 落成真实用例（node 面），并在 PROGRESS 记为待办（R-WEB-F1：`channels/web/` 纳入强制名单，随施工单 14 一并做）。**不能只说"测试够了"而不留痕。**

### A-7（P2）CLI 不能按 profile 名分支

- **发现**：`run.ts` 现有逻辑要求 `--prompt`，直接跑 web profile 会以 `prompt-missing` 退出；最省事的写法是 `if (profile === 'web') 启动服务`——这违反施工单 06 §5"代码里没有渠道分支"。
- **处置**：新增渠道无关的 `--serve`（"常驻直到 SIGINT"），任何 profile 都能用（v1.1 §9.2）。

### A-8（P2）端口占用不得自动换端口

- **发现**：自动 `port+1` 在演示现场意味着"浏览器开着 7331，服务其实在 7332"。
- **处置**：`EADDRINUSE` → `BahError('web-listen-failed')`，进程退出码 1，文案给出占用端口。

### A-9（P1）POST 响应与 SSE 帧的竞态

- **发现**：`POST /api/turn` 返回 202 时，`user/message` 帧可能已经先到；若前端"POST 成功 → 本地插入一条用户气泡"，就会双份。
- **处置**：前端**不据 POST 响应改状态**（v1.1 §7 末条）。所有可见状态只来自帧。这也是 T-WEB-001 幂等性的另一面。

### A-10（P2）静态资源目录穿越

- **发现**：`GET /styles/../../etc/passwd` 这类请求若直接 `join(root, url)` 会读到仓库外文件。
- **处置**：解码后规范化，必须仍在 `staticRoot` 前缀内；否则 404（不返回 403，避免探测）。

## 3. 角度 B：视觉 / 交互 / 可访问性 / 演示

### B-1（P0）两套视觉指令正面冲突

- **发现**：施工单 13 §2 要"Apple 设计语言：严格圆角、cubic-bezier、毛玻璃层次"；自研 BAH DS `SKILL.md` 要"quiet by default、避免装饰性渐变/发光/假图表、表面逐级加深"。两者都自称标准，实现者会二选一，另一方必然不合格。
- **仲裁**：用户明确"所有前端都要遵守这个标准（BAH DS 自研设计系统）"，因此**取值服从令牌**，只保留 Apple 的取向（圆角一致性、缓动、层次）。毛玻璃限定两处：顶栏、弹窗遮罩；底色仍走 `--bg-menu`（v1.1 §2.3）。
- **反例记录**：不允许出现"品牌色渐变按钮""发光边框""装饰性大圆角卡片"。这类东西在答辩现场会被问"这跟 BAH DS 令牌什么关系"。

### B-2（P1）三态只靠颜色 = 色弱不可用

- **发现**：v1.0 只写"成功/拒绝"标签，实现极易退化成红绿两色。
- **处置**：三重编码——颜色（`--status-*`）+ 文案（待执行/已完成/被拒）+ 图标（本地 SVG，`aria-hidden`）。审计面板同理。

### B-3（P1）"标灰"不足以表达"待确认"

- **发现**：灰色在 BAH DS 里同时表示 disabled / 次要信息 / 占位。仅靠灰会让用户以为是"加载中"。
- **处置**：金额位渲染 `¥ —` + `.ds-tag--warning` "待确认"，并给 `aria-label="金额待确认：本回合没有工具结果"`。

### B-4（P1）弹窗焦点管理

- **发现**：v1.0 未写焦点行为。审批弹窗是**资金操作**的唯一拦截点，键盘用户若 Tab 到背景按钮，会绕过审批语义。
- **处置**：打开即聚焦"拒绝"按钮（安全默认），`Tab` 循环锁定在弹窗内，`Esc` = 取消，关闭后焦点回到触发元素。

### B-5（P1）SVG DAG 对屏幕阅读器是空白

- **处置**：`<svg role="img" aria-label="…摘要">`，每节点 `<title>`；另给一段文字摘要（"本回合 3 个节点，1 个被阻断"）。

### B-6（P2）三栏在小屏挤压

- **处置**：`≥1120px` 三栏；`840–1120px` 侧栏折叠为底部抽屉；`<840px` 单列 + 顶栏切换（复用移动端施工单 14 的断点约定）。

### B-7（P2）流式渲染的布局跳动

- **发现**：delta 追加会让气泡高度持续变化，长对话里滚动位置会"跳"。
- **处置**：`overflow-anchor: auto`（浏览器原生锚定）+ delta 期间禁用"自动滚到底"以外的手动滚动干扰；金额与序号统一 `font-variant-numeric: tabular-nums`，避免数字宽度抖动。

### B-8（P2）答辩时"看不到证据"

- **处置**：审计面板顶部三个计数（审批 / 拒绝 / 阻断），理由码等宽字体；工具卡片显示 `callId` 短码，可与审计条目对照。这是"可解释"的可见化，不是装饰。

### B-9（P2）失败态缺失会打断演示

- **处置**：连接断开 → 顶部 `.ds-alert--warning` 横幅 + "重试"；空会话 → `.ds-empty` 给三幕提示（正常转账 / 注入拦截 / 知识拒答）；接口 4xx/5xx → 行内 `.ds-alert--danger`，不弹 alert()。

## 4. 仲裁与放行

| 冲突 | 角度 A 主张 | 角度 B 主张 | 仲裁 |
|---|---|---|---|
| 视觉标准 | 令牌优先，避免自造 | 需要"高级感"支撑答辩 | **令牌优先**；高级感来自排版与留白，不来自效果 |
| DAG 数据源 | 换源 + 登记偏差 | 演示需要"像规划图" | 换源，但**保留泳道与阻断传播**，视觉上仍是"图" |
| 覆盖率 | 应扩名单 | 不应拖慢交付 | 本次不扩，登记 R-WEB-F1 |
| 流式 | 必须 ephemeral | 断线后不能留半句 | 一致：断线丢 delta，权威消息补齐 |

**放行条件（P0 关闭证据）**

1. A-1 依赖翻转 → `pnpm typecheck` 通过且 `pnpm why @bah/channels` 无环。
2. A-2 DAG 换源 → `dag.test.ts` 断言 blocked 传播 + 文档 R-WEB-D1 存在。
3. B-1 视觉仲裁 → `app.css` 无裸色值（`verify-web` 门禁）+ 仅两处 `backdrop-filter`。

**未关闭的下游项**：R-WEB-D2（fork）、R-WEB-D3（坐席接管）、R-WEB-F1（覆盖率名单）——均已在 PROGRESS 与本文档登记，不阻塞本次交付。

## 5. 审核结论

- 规格覆盖：施工单 13 的 6 条出口全部有落点与用例；3 条交互细节中 2 条延后并登记偏差，1 条（中断）本次实现。

### 端到端实录（本机）

```text
pnpm web → bah: profile web · 会话 s-… · 常驻中
GET  /api/health   → {"ok":true,"lastSeq":1,"pendingTickets":[]}
POST /api/turn     → 202；3s 后 pendingTickets:["ticket:call-1"]（人在环，不自动放行）
POST /api/approval/ticket%3Acall-1 {"decision":"allowed-once"} → 200
帧流：approval(转账/¥800.00/王建国/黄级/理由必填) → approval-closed(已批准一次性)
      → tool(done, amountConfirmed=true, 正文含流水号与余额) → message(收尾)
审计：审批请求 → 票据已签发 → 票据已批准 → 审批结论 → 工具完成 → 票据已核销 → 票据已消费 → 轮次结束
```

**结论**：五视图可用、审批链路真实（不是演示桩）、金额与风险提示可追。剩余偏差 R-WEB-D1/D2/D3/D8/F1 均已在文档与 PROGRESS 登记。
