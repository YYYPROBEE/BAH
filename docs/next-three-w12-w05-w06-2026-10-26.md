### 2.2 三处必须先裁决（否则会造出第三份 `TicketRef`）

**裁决 A：一份既有 `TicketRef` 都不改。**
新建独立 `TicketLease = { leaseId, ticketId, expiresAt }`，**通过 `ticketId` 关联**，不做字段合并、不做继承。

- 注：`expiresAt` 在 core 那份里**早就有**（施工单 v1 写"增 expiresAt"是把两份搞混了）。
- 关系钉死：`lease.expiresAt <= ticket.expiresAt`，装配期 fail-loud；`renew()` 只前移 lease，不动票据 TTL。
- `interaction` **不许 import `@bah/runtime`**：lease 由 host 随票据一起注入，否则新增包依赖边。

**裁决 B：`reverse(txnId)` 的幂等键是 `txnId`；日额度要不要回退？**
冲正必须落**两条流水**（原交易 + 冲正），不是删原记录。**先读 mock 的额度算法再定**：


若额度是"当日 `transfer` 流水求和"，那冲正流水必须能被识别成负向（或单独分类），否则额度不会回退。
口径二选一并在文档写清：**额度回退**（冲正 = 该笔业务未发生）或**不回退**（额度是"用过多少"的合规口径）。
建议回退，但**两条流水都要在**——对账要看得见"发生过、又退回来了"。

**裁决 C：回滚开关挂哪一层。**
施工单写 `saga.compensation.enabled: false`，但 `bank:saga` 的 `features` 只有 `b1..b4`，
且报错文案把可用键写死成"可写：b1 / b2 / b3 / b4"——**加 b5 就是改动被文案锁定的枚举**。

## 5. 每单都要念的纪律（七条）

1. `NODE_EXTRA_CA_CERTS=` 前缀**不能省**（本机该变量指向不存在的证书，会打红"stderr 必须为空"的断言）。**改环境，不改断言。**
2. **不许并发跑两个 vitest**：子进程用例会因 CPU 争抢假红。
3. 前台跑全量 vitest 可能被 SIGTERM 且无输出 → 后台跑并落盘（`.ci-artifacts/`），再看最后两行统计。
4. 新建 `.ts` 必须 `git add`，否则 `tracked-sources` 门禁红（本仓实测过）。
5. 文档里反引号包裹的仓库路径**必须真实存在**；**未来才存在的路径不许写进反引号**（`docs-paths` 扫 `docs/*.md` 与 `PROGRESS.md`）。
6. 改配置面后必须 `npx tsc -b tsconfig.host.json tsconfig.client.json`（只跑 vitest 会漏类型红）。
7. 数用例用 `npx vitest list | grep -c " > "`；覆盖率**行口径与包口径差 15 个百分点以上**，写文档必须二选一。

**五条红线**：R-1 不改 `core/api.ts` 契约面；R-2 零运行时依赖；R-3 工具只走 `new ToolPipeline(...).execute()`；
R-4 `runtime/src/plan/` 只许 import core/util/相对路径；R-5 金额禁 float 与 `Number()`。

**熔断**（触到就停下汇报，不许硬推）：单会话 >90 分钟未完成 / 三绿连续 3 轮不过 /
核实命令描述的对象不存在 / 需要改红线 / 累计 >30 小时而进度 <70 人日。
