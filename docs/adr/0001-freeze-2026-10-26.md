# ADR-0001 · 三件契约冻结（2026-10-26）

- **状态**：已接受（Accepted）
- **日期**：2026-10-26
- **版本**：`v1.0.0-frozen-2026-10-26`
- **相关**：`docs/contracts/tool-contract.md`、`event-table.md`、`scenario-dsl.md`

## 1. 背景

工具契约、事件表与场景 DSL 是三处会被多个能力同时消费的"形状"。如果每项能力各自起名：

- 同一含义出现两个键（`safety/halt` vs `safety/halted`），门禁无法反向覆盖；
- 载荷字段各写各的（有没有 `at`、`planId` 是必填还是可选），日志链无法解释；
- 每个评测场景都要顺手改一次引擎，改动面会从局部扩散到全仓。

## 2. 决策

**在扩展能力开工前，把三件"形状"冻结下来，之后只增不改。**

| # | 冻结内容 | 代码真相源 |
|---|---|---|
| 1 | 工具契约（`argsSchema` / `resultSchema` / `validateAt`） | `packages/util/src/tool-contract.ts` |
| 2 | 事件表（既有 6 键不改 + 新增 5 键 + 1 处枚举扩展） | `docs/contracts/event-table.md` |
| 3 | 场景 DSL（`ScenarioSpec`） | `packages/eval/src/scenario/spec.ts` |

**落点为什么在 `@bah/util` 而不是 `@bah/runtime`**：
`packages/bank/package.json` 的 dependencies 只有 `@bah/core` / `@bah/safety` / `@bah/util`。
工具 schema 要在 `packages/bank/src/tools/specs.ts` 里声明 —— 若契约落在 runtime，
bank 必须新增 `@bah/runtime` 依赖边，会改变包图并引入环的风险。

**schema 位置为什么是泛型而不是 `ToolSchema`**：
`@bah/core` 的 dependencies 含 `@bah/util`，所以 util 反向 import core 会成包级环。
泛型留位 + 使用方代入，既不复制 core 的类型（避免第二真相源），也不成环。

## 3. 后果

**正面**：

- 后续能力不再需要为"事件叫什么"重复协商；门禁的反向覆盖可以一次配对；
- 评测场景只填数据不改引擎。

**负面（必须承认）**：

- **冻结过早的风险**：开工后发现字段不够。处置：允许**一次**改签，不推倒重来。
- **`validateAt` 是单一字段**，无法区分入参与出参的校验时点。本 ADR 明确其语义为
  "只描述入参时机，出参恒为 `post-execute`"，并在 `docs/contracts/tool-contract.md` §2.3 记了
  这个已知窄口。要分别配置走后续 ADR，**不许直接加字段**。

## 4. 改签流程

1. 提 ADR，写清：改什么 / 为什么现在才发现 / 影响哪些模块 / 要不要重跑哪些用例；
2. 由维护者签字；涉及事件表改动的，额外需要该事件的消费方会签；
3. 版本号：加字段 = minor，改语义 = major；
4. **签字记录写在本节下方**，没有签字行的一律视为未批准。

**v1.0.1 自审修正的三条**（下游均未开工，v1.0.0 从未被代码消费，故不计入改签名额）：

| # | 洞 | 补法 |
|---|---|---|
| 1 | 场景 DSL 缺**否定断言** —— dry-run 的核心是"零 `tool/call`"，`event` 只能断"出现" | 加 `no-event` kind |
| 2 | 场景 DSL 缺**审批应答维度** —— `profiles/headless` 把 `autoDecision` 固定成 `allow`，P 族场景会跑出同一结果 | 加 `approval: 'allow' \| 'reject' \| 'unavailable'`（对齐 `ApprovalSettings`，不发明第四种） |
| 3 | 工具契约**示例字段名写错** —— 写 `balance`，实际 `TransferResult` 是 `balanceCents`（无 `balance`）；且入参元、出参分 | 示例照 `provider.ts:146` 逐字抄，并加单位警示 |

> **第 3 条是最危险的一条**：错的示例不会报错，只会让实现把出参边界按"元"写，差 100 倍。
> 它同时证明一件事——**冻结文档里的示例必须从代码抄，不能凭印象写**。

## 5. 与权威序冲突时

仓库权威序：**代码现状 > 契约 > 规划稿**。
若本 ADR 冻结的形状与代码现状冲突，**以代码为准，并立即回到本 ADR 记偏差**——
不许"按文档改代码"。
