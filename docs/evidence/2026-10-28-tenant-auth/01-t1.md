## 0 施工位置：为什么不在主工作树

`00-全局约定.md` §8 的第一条是"开工先判归属"。开工时主工作树的状态（原文）：

```

113     （全部属可观测性/策略外置并行会话：telemetry / metrics / prometheus / alert-* / logging…）
```

判归属：那批改动**不属于本单**，且与本单要改的文件重叠（`boot.ts` / `persistence.ts` /
`audit-decisions.ts` / `web.ts` / `metrics.ts` / `util/src/index.ts` / `chain-file.ts`）。
并行会话在**开工前 2 分钟**还在写盘（`docs/web-frontend.md` `2026-10-29 00:16:17`）。

⇒ 两条路都不可行：在主树上直接提交会把别人的在制改动卷进本单；在主树上 `git add` 部分文件

**处置**：用独立 worktree 施工（这也正是本仓并行会话的既有做法——开工时仓库里已有

### 1.3 两条环境事实（如实登记）

1. **CRLF**：本机 `core.autocrlf=true`，`git worktree add` 检出的文件是 CRLF，而主树是 LF。
   这会让所有**内容摘要**类判据整片打红：

   ```
   $ npx vitest run | grep -c '^ FAIL'
   … knowledge.test.ts (10 failed)：语料摘要不匹配：packages/knowledge/fixtures/corpus.json
   … policy compile / sentry-rules / main.smoke 同样红
   ```
   **处置：把 worktree 的文本文件统一成 LF**（1229 个文件）。处置后 `git status` 里
   **只剩本单自己的改动**（`git add -A` 实测 21 个文件，见 §2 末尾）。
2. **`LANG`/编码**：PowerShell 读 UTF-8 文件需 `-Encoding UTF8`；否则中文变 mojibake，
   容易把"文档写错"和"终端读错"混为一谈。命令表按 `00` §2 原样使用（前缀
   `NODE_EXTRA_CA_CERTS=` 本机为空串，仍按纪律保留）。

### 1.4 基线口径（两处"看起来是红、其实是陈旧基线"）

| 门禁 | 红项 | 是不是本单引起的 | 处置 |
|---|---|---|---|
| `assertions` | `packages/channels/src/web/project.test.ts: 断言从 74 降到 73` | **否**——`git diff` 对该文件为空，`6af6d64` 上就是这样 | 收尾同批 `--update` 重登记（基线 7887 条 → 8009 条 / 256 文件），并在 §4 登记 |
