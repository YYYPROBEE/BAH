## 1 A 类 · 造假探针（我写的功能是不是真的）

### A1 `plan_arm` 的 `projectContent` 会冲掉结构化出参 —— 【P0，已修】

- **声明**：`replayArmedPlans` 与计划卡都"从 `tool/result` 的结构化 JSON 重建"。
- **实际**：`ToolPipeline` 在有 `projectContent` 时用**投影文本**作为 `tool/result.content`。我给 `plan_arm` 写了一段人话投影 → 落账内容不是 JSON → 回放 `JSON.parse` 直接抛 `window-replay-invalid`，计划卡也读不到字段。**同一条改动让"可回放"与"计划卡"同时断粮。**
- **证据**：`packages/host/src/boot/plugins/plan.ts`（删除前 1231 行附近）与 `packages/runtime/src/tools/pipeline.ts` 的 content 生成路径。
- **修法**：删除 `plan_arm.projectContent`，出参与 `goal_set` 同口径（默认 JSON）。
- **复验**：`packages/host/src/boot/plugins/authorization.test.ts` 断言 `armed` 是可读对象，且二次唤醒 `skipped/already-ran` 依赖 `plan/created` 派生；集成用例通过。

### A2 `fact_forget` 的黄级是装饰品 —— 【P0，已修】

- **声明**：删除类操作"走审批通道 + 打字确认"。
- **实际**：`bank/src/tools/governance.ts` 第 344 行 `if (!BANK_TOOL_NAME_SET.has(input.name)) return next(payload)` —— 非银行工具**直接放行**。`fact_forget` 虽然声明 `tier:'yellow'`，但没有任何一层会为它签票据/等应答。**这正是方案 §0 点名的坑，我在实现里原样踩了一遍。**
- **修法**：新增 `packages/host/src/boot/plugins/ask.ts` 的 `askForNonBankTools`（照抄"先 `await next()` 再 ask"），`fact:store` 为 `fact_forget` 注册。
- **复验**：`packages/channels/src/web/adapter.test.ts` 新增三例（缺确认词/错词/正确词），并在 `authorization.test.ts` 的 headless 审批环境里跑通删除路径。

### A3 "重启补跑"原先不成立 —— 【P1，已修】

- **声明**：关掉 App 再开机，到期计划会补跑（06 的核心承诺）。
- **实际**：host **从不加载既有会话**：`core:persistence` 只订阅 `session/event` 写盘；`JsonlPersistence.create()` 遇到已存在文件直接 `session-exists`；`plan:dag` 的 armed store 在 apply 期 replay 的 `session.events()` 永远是空数组。也就是说：调度器补跑的是"当前进程内存里的账本"，进程一关就没了。**这与 01 报告对 00 方案 D1 的判定是同一类错误。**
- **修法**：
  1. `RunContext.restoreSession` + `boot()` 在**任何插件装配前**读 `session.jsonl`（`packages/host/src/boot/boot.ts`）；
  2. `provideSession` 新增 `restore` 选项，`SessionStore.restore()` 灌日志（不广播，避免二次审计）；
  3. `core:persistence` 对既有会话改走 `backend.open(dir,{mode:'write'})` 续写；
  4. `bah plan ...` 默认 `restoreSession: true`。
- **复验**：`authorization.test.ts` 的「重启补跑」用例：进程 A arm 后 dispose，进程 B 用同一 `jsonlDir` + 会话 id 启动，**无人工干预**在 200ms 内产生 `plan/created` 并完成转账。这条现在是实测，不再是话术。

### A4 boot 补跑的一次性微任务可能被吞 —— 【P1，已修】

- **实际**：`queueMicrotask` 只跑一次；若 `plan:scheduler` 排在 `plan:dag` 之前，`ctx.get(PLAN_WAKE_SERVICE)` 抛 `service-missing` 后**静默返回**——"看起来会补跑，其实永远不补"。
- **修法**：50ms 重试最多 20 次，最终失败 `logJson('warn','host.plan-catchup-unavailable')`；一次性计时器 `unref` 且在 dispose 清理（不是第二个触发时钟）。
- **复验**：上面的重启用例把 scheduler 放在最后一行仍能补跑（正是这条重试生效的场景）。

## 2 B 类 · 契约探针（声明—发射—投影—消费）

### B1 计划卡的实例键永远为空 —— 【P1，已修】

- **实际**：`ArmedPlan` 没有 `occurrence` 字段，`plan_arm` 出参自然也没有；计划卡投影读 `payload.occurrence` → 空串。
- **修法**：投影层用 `occurrenceOf(recurrence, dueAt)` 纯函数现算（与运行时幂等键同源），不依赖出参里的冗余字段。
- **复验**：`packages/channels/src/web/project.plan-card.test.ts` 断言 `occurrence` 与运行时口径一致。

### B2 计划卡的四块信息与 `ConfirmText` 帧字段 —— 【通过】

- `PlanCardFrame` 已进 `WebFrame` 联合、`frameKey`（按窗口替换）、`project.ts` 产出、桌面/移动消费者、`docs/contracts/frame-table.md`。
- `ApprovalFrame.confirmText` 由 `confirm.ts` 单一真相源产出，服务端在 `http-adapter.decide()` 校验（前端只做提示）。
- **复验**：`scripts/verify-frame-closure.ts` 四条判据全绿（17 个 kind，含 `plan-card`），反例自测 7 例全绿。

### B3 `plan/created` 派生幂等的口径 —— 【通过，附边界】

- `executedInstanceKeys` 只认 `plan/created`（含 `planId`/`at`），要求 `at >= armedAt` 且周期实例键相同。
- **边界（诚实写清）**：武装后若用户手动 `plan_execute` 跑过同一计划，同一实例会被视为"已执行"——这是"同一实例不重复扣款"的预期，不是 bug，但答辩要能解释。

## 3 C 类 · 安全探针

### C1 `plan_wake` 对模型隐身 —— 【通过】

- `ToolDefinition.exposure='internal'`，装配侧在 `toolDescriptorsOf`/`toolSpecsOf` 过滤；注册表仍可取（宿主/CLI 需要）。
- **复验**：`packages/runtime/src/agent-loop/request.test.ts` 新增用例：`plan_wake` 不在模型 schema，`plan_arm` 在。

### C2 判定时刻上界 —— 【通过】

- `duePlans` 内建 `maxSkewMs=5min`，越界返回 `window-clock-ahead` 且**一条都不执行**；`checkWindow` 也独立再判一次（双保险）。
- **复验**：`authorization.test.ts` 传 `at = now + 1h` → `ok:false`、`entries` 为空、零 `plan/created`。

### C3 预算上限只是记账 —— 【P1，已修】

- **实际**：`budgetCents` 只存进窗口，执行期没有任何校验 → "不擅自加价"是口号。
- **修法**：wake 执行前累加 `transfer_create` 节点的**静态**金额，超过预算即 `downgraded`（`amount-within` 失守），不执行。
- **已知限制**：动态 args（`${node.<id>.<path>}`）算不出金额，会漏算。**不假装覆盖**，登记在 §4。

### C4 删除确认不靠点选 —— 【通过】

- `confirmText` 只在服务端判定；`fact_forget` 通过 ask 通道拿票据（A2 修复后），`ChoiceFrame` 未被用作审批。
