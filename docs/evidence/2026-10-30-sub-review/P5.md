## A · 造假探针

| # | 探针 | 结论 |
|---|---|---|
| A1 | `risky-calls` 是否被说成「熔断」？ | 否。它只把第 N 次非绿调用的理由从 `declared` 改为 `risky-calls`（仍走审批）；真正的硬挡是 sentry 的 `budget.riskyCalls`（既有能力） |
| A2 | 预算 6 是否拍脑袋？ | 演示需 3 次非绿调用（sub_cancel / sub_authorize / sub_watch），6 = 2 倍余量；预算是会话级、预执行即扣、重跑不退 |
| A3 | 审批卡是否声称知道合约到期日？ | 否。`presentCall` 是同步纯函数，拿不到 core 的异步快照；卡上写「若仍在合约期会被硬拦」，具体日期由工具结果与硬拦错误给出，不编造 |

| # | 探针 | 结论 |

| C1 | 商户名注入提示词 | 新增 `sanitizeMerchantForPrompt`（NFKC/控制符/零宽/双向控制/折叠空白/单行/32 码点），`sub_list`/`sub_watch`/`sub_authorize`/`sub_cancel` 的 `projectContent` 全部过它 |
