## 0. 一句话结论

桌面壳**真的跑起来了**：`electron .` → `desktop.host-ready port=10259` → 窗口加载
`http://127.0.0.1:10259/` → `bah:boot/ready` 收到 → `bah:boot/injections` 发出 →
关闭时 `desktop.host-stopped` + `bah:boot/shutdown` 各一条。
四消息里三条已在真机日志中实测，第四条（`fatal`）的**投递边界**被显式收窄并写进代码注释。

过程中撞到 **6 个"方案与平台不符"的硬点**，全部按事实修正（不是绕过）：`probe:false`
会让端口永远是 0、固定会话 ID 会让持久化静默全丢、把 workspace 包打进 bundle 会让
21 处 `instanceof BahError` 失效并打断沙箱的文件定位、`bank:knowledge` 缺签名密钥会让
启动直接失败、`preload.cts` 在 `verbatimModuleSyntax` 下不能 `import`、
`shutdown` 消息在 `before-quit` 阶段已无渲染进程可投递。

出口：门禁 **51/51**、`pnpm test` **302 文件 / 3384 例全绿**、桌面端 9 条负控逐条变红。

| 消息 | 实测 | 证据 |

## 3. 对抗式审查：发现的缺陷与修正

| ID | 缺陷（严重度） | 现场 | 修正 |
|---|---|---|---|
| **F-02-01** | 方案 `probe:false` 与 `port:0` **互斥**（致命） | `web/listen.ts:bindPort()` 第一行 `if (probe === false) return port`——它是给 `--dump-config` 用的"只装配不占端口"。桌面端写 `port:0` ⇒ `DESKTOP_SERVER.port === 0`、地址变 `http://127.0.0.1:0/`，窗口必然打不开且不是崩溃（是一句 `bad port`） | `boot.ts` 显式 `probe: true`，并把"离线不探 RAG"改由 `bank:knowledge.required:false`（现在是整行移除）保证。注释里写明为什么不能照抄方案 |
| **F-02-02** | 固定会话 ID 会让**持久化静默全丢**（致命） | `jsonl:create()` 对已存在会话排他失败（`会话已存在，拒绝覆写`），且没有任何调用方用 `open(mode:'write')`；`provideSession()` 也不回放磁盘。固定 `desktop-demo` ⇒ 第二次启动起每条事件都写不进磁盘，只留 `runtime.session-listener-failed`，**界面照样能用** | 改为 `desktop-<yyyyMMdd>-<HHmmss>`（`session-id.ts`，纯函数 + 4 例）；跨启动历史改用 `pnpm bah audit --dir`。方案里的"演示幕 4 重开看历史"据此改写，见 §4 D-02-4 |
| **F-02-03** | 把 `@bah/*` 打进 bundle 会**破坏错误分类与沙箱定位**（致命） | ① 内联一份 `@bah/util` + 外部包再 `import` 一份 ⇒ 全仓 **21 处** `error instanceof BahError` 跨副本恒 `false`；② `@bah/safety` 的 `packageRoot()` 从 `import.meta.url` 向上找自己的 `package.json` 决定 worker 路径，内联后起点是 `dist/main.mjs` ⇒ 启动直接 `bah-sandbox: package-root-missing`（第一次真跑就是这个错） | 取消 `noExternal`：主进程只产接线（1.8 MB → **27.6 KB**），依赖靠 `node_modules` 真实目录。03 用扁平化拷贝把 @bah 闭包放进 `resources/app/node_modules` |
| **F-02-04** | `bank:knowledge` 让桌面端**永远起不来**（高） | `signature` 在 boot 期校验语料签名密钥，缺 `BAH_KNOWLEDGE_KEY` 直接 fail-loud；双击 exe 的用户没有地方设环境变量。`required:false` 只管 sidecar 探活，管不到签名 | desktop profile **整行移除** `bank:knowledge`（不写 = 不装配 = 无该工具）。代价显式登记：桌面端没有 `knowledge_*` 工具 |
| **F-02-05** | `preload.cts` 在 `verbatimModuleSyntax` 下**不能 import**（中） | `TS1286: ECMAScript imports and exports cannot be written in a CommonJS file`。而 preload 又必须复用 `./ipc.ts` 的四个通道名（否则要么重复字符串、要么违反单一定义） | 源文件改 `preload.ts`（ESM 源码）+ tsdown `format:['cjs']` ⇒ 产物仍是 `dist/preload.cjs`（实测首行 `let electron = require("electron")`）。判据落在**产物**而非后缀 |
| **F-02-06** | `shutdown` 消息**永远发不出去**（高） | 第一条实测日志里没有 shutdown：`WM_CLOSE` → 窗口 `closed`（渲染进程销毁）→ `window-all-closed` → `app.quit()` → `before-quit`，此时 `mainWindow` 已是 `undefined` | 在窗口 `close` 阶段**先拦一次**（`event.preventDefault()`）→ dispose → 发 shutdown → 再 quit；`quitting` 标志防自锁。改后实测 shutdown 一条 |
| **F-02-07** | 门禁 G1 假绿（高） | 第一版用 `windowOptions.includes('sandbox: true')`，而同一文件的接口声明 `readonly sandbox: true` 也会命中 ⇒ 把常量改成 `false` 门禁照样绿（负控实测 `exit=0`） | 判据改成只在 `HARDENED_FLAGS` **常量对象块**内比对；负控随即变红 |
| **F-02-08** | 门禁 G2 假绿（高） | 暴露面正则只认 `[,:]`，四个方法里只匹配到 `sendReady`（1 个）；因 `extraKeys` 为空而"通过" | 正则改 `^\s{2}(\w+)\s*[(:,]`，并加**正向计数**（必须恰 4 个）——解析失败或少暴露一个都会红 |
| **F-02-09** | tsdown 的 `external: ['tsx']` 只匹配裸名（低） | dev 分支 import 的是子路径 `tsx/esm/api`，被打进 bundle：多出 `api-*.mjs` / `lexer-*.mjs` 两个分片，便携 zip 里没人管 | `external: ['electron', /^tsx(\/|$)/]`，产物回到 2 个文件 |
| **F-02-10** | 负控脚本对**未入库文件**无效（流程缺陷） | `git checkout -- apps/desktop/src` 对 untracked 文件是 no-op ⇒ 8 个变异**累积**在一起，输出无法归因 | 先把 02 文件 `git add` 再跑负控；并把这条写进 §3.2 的复现说明 |

### 3.1 负控（逐条注入 → 门禁必须变红）

`bash .tmp-neg-02.sh`（一次性，不入库）。**9/9 全部变红**：

| # | 注入 | 实测命中 |
|---|---|---|

| G2 | 暴露面加 `ipcRenderer,` | `G2 … 应恰为 4 个方法（实际 5：…,ipcRenderer,sendReady）` + `把 'ipcRenderer' 放进了暴露面` |
| G3 | 加第五个通道 `'bah:tool/click'` | `G3 … 出现表外 IPC 通道 'bah:tool/click'` |
| G4 | 去掉 `setWindowOpenHandler` | `G4 … 缺 setWindowOpenHandler → { action: 'deny' }` |
| G5 | `loadURL` 写死 `http://127.0.0.1:7331/` | `G5 … 必须用 DESKTOP_SERVER 给的 instance.url` |

另有三条**运行期**对抗（不是门禁，是人工实测）：

| 攻击 | 结果 |
|---|---|
| `ELECTRON_RUN_AS_NODE=1`（本机环境默认带着）| 此时 `electron.exe` 是纯 Node：`require('electron')` 返回 **exe 路径字符串**，`app` 是 `undefined`。所有启动/验证命令都必须 `env -u ELECTRON_RUN_AS_NODE`，已写进文档 |
| 用 `taskkill /F`（强杀）退出 | 没有 `desktop.host-stopped` / `shutdown`——强杀不给 `before-quit`，属预期；文档写明"优雅关闭 = 点关闭按钮" |
| 第二次双击（单实例锁）| 不新建窗口（`requestSingleInstanceLock` 返回 false → `app.quit()`）；`second-instance` 聚焦已有窗口 |

### 3.2 门禁覆盖不到的两件事（如实登记）

1. **"窗口里真的渲染出了页面"**：日志只证明 `loadURL` 成功返回，不证明 DOM 起来了。
   截图证据放 03 的离线演示（T-DTB-003）。
2. **`apps/desktop/src` 不在覆盖率强制名单里**：`scripts/coverage-allowlist.ts` 的
   `package` 字段只支持 `packages/<dir>`，无法指向 `apps/desktop`。37 条用例实际覆盖了
   全部纯模块（行覆盖近 100%），但**没有门禁钉住**。属既有机制的限制，见 §5 R-02-03。

## 4. 与施工单的偏差登记

| ID | 02 文档原文 | 实际做法 | 原因 |
|---|---|---|---|
| **D-02-1** | `apps/desktop/src/preload.cts` | `preload.ts`（ESM 源）+ tsdown `format:['cjs']` | F-02-05：`.cts` 在 `verbatimModuleSyntax` 下不能 import，无法复用 `ipc.ts` 常量 |
