## 2. 逐条：判据 / 复验方式 / 为什么这样判

| # | 判据（脚本实际做的） | 为什么这样判 |
|---|---|---|
| I-DT-01 | ① `profiles/desktop/patch.yml` 的 `channel:desktop.host === '127.0.0.1'`；② `main.ts` 含 `startDesktopHost(`（证明是**进程内**宿主，不是去连外部服务）；③ `apps/desktop/src/**`（去整行注释、去测试）不含 `http(s)://` 非 loopback | 三条合起来才等价于"私有宿主"。只查 host 会漏掉"主进程其实在连 `pnpm web`"；只查源码会漏掉 profile 被改宽 |
| I-DT-02 | `port === 0` + `loadURL(instance.url)` + `ctx.get(DESKTOP_SERVER)` | 写死端口的失败方式不是崩溃，是"上一次能用这次不能"；三条一起才能排除"读了但没用" |
| I-DT-03 | `HARDENED_FLAGS` **常量块**内四个硬值 + 窗口用 `hardenedWebPreferences()` | 在整文件里搜子串会被**接口声明**（`readonly sandbox: true`）满足 —— 这是 02 单实际踩到的假绿 |
| I-DT-04 | 五个处理器逐个存在；`window.open` 必须落到 `action: 'deny'` | 少任何一个就是一条绕过路径；`setWindowOpenHandler` 存在但返回 `allow` 同样致命，所以查 `deny` |
| I-DT-05 | 四个消息名逐一存在 + `BOOT_INJECTION_KEYS` 恰 5 键 | 多一个键 = 载荷协议变了；少一个 = 某条生命周期事实没人接 |
| I-DT-06 | 载荷键无 `token` 字样 + 有 `FORBIDDEN_PAYLOAD_KEYS` + `main.ts` 发送前 `assertNoCredentialKeys` | 只靠"注释里说不放 token"不可验；黑名单 + 发送前断言才是机器判据 |
| I-DT-07 | desktop patch **不含** `bank:knowledge` + `core:model.provider === 'router'` | `required:false` 管不到签名密钥（01 的 F-02-04）；离线口径必须是"装配层就没有外部依赖" |
| I-DT-08 | `boot.ts` 显式 `jsonlDir: resolveSessionsDir(options.userData)`；`paths.ts` 的 userData = `<appData>/bah-desktop` | `core:persistence.root` 相对 cwd，不覆盖就会写进 `resources/app`（安装目录通常只读） |
| I-DT-09 | `git diff --stat 1c369b3 -- apps/web` 输出为空 | 这是"复用 Web UI"的**唯一**客观判据；"我没改"不可验证 |
| I-DT-10 | 打包脚本含 `npmmirror.com`，不含 `github.com` / `electron-builder` / `electron-packager` | 本机到 GitHub 的 443 不通；一旦有人换回 builder，构建会随机失败且难查 |
| I-DT-11 | `requestSingleInstanceLock()` + `second-instance` 聚焦 | 两个进程会各自写同一份 `userData/sessions`，第二个窗口还会显示另一份状态 |
| I-DT-12 | `.npmrc` 有 `electron_mirror` + 根 `package.json` 的 `pnpm.onlyBuiltDependencies` 含 `electron` | pnpm 10 默认阻止 postinstall ⇒ 二进制根本不下载，报错却是"Electron failed to install correctly" |
| T-DTB-008 | zip 存在 + **重新算** sha256 与 `desktop-sha256.txt` 记录逐字相等 | 记录和产物必须能对上；重新打包忘更新记录 → 这条红（故意的） |
| T-DTB-010 | `bundles.ts` 的候选数组顺序是 `[index.ts, index.js]` + 解压包里**实际**有 `bundles/base/index.js` | 只查源码会漏"包里没带那个文件"；只查包会漏"本机开发跑了打包产物" |
| T-DTB-012 | 解压目录里 `resources/app/{sessions,memory.db,saga.sqlite}` 都不存在 | 只读目录里出现会话产物 = 换机/权限事故的第一步 |
| DOC-01 | `docs/desktop.md` 有「启动/离线演示/打包/故障排查」；`NOTICE.md` 有 Electron；`docs/deploy.md` 有 `desktop:pack` | 文档缺一节，现场就少一条自救路径 |

## 4. 两条"跳过即可"的边界（脚本里显式标 `－` 而不是假装通过）

1. **`dist-desktop/` 不在版本库**：干净 clone 上 `T-DTB-008` / `T-DTB-010`（包内文件）/ `T-DTB-012`
   会显示 `－ 跳过`，并打印"先跑 `pnpm desktop:pack`"。这是刻意的：132 MB 的产物不该入库，
   但验收不能因此假装通过。
2. **解压目录**：`T-DTB-012` 需要一份解压出来的包（脚本默认看
   `<项目集根>/temp/BAH 桌面 测试/BAH`）。换机器跑时按 `docs/desktop.md` §6 解压到任意位置，
   改脚本顶部的 `UNPACKED` 即可。
