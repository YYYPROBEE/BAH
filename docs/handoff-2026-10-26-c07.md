## 4. 没做完的 / 不在本包范围

1. **覆盖率命令与任务书不同**：任务书写 `--coverage.reportsDirectory=.ci-artifacts/cov-facts`；
   实际用 `pnpm test:coverage:all`（`coverage-summary.ts` 固定读 `.ci-artifacts/cov-all`，
   改目录会让判据脚本读不到）。`clean:false` 已在 `vitest.coverage.config.ts` 里，未改。
2. **本次覆盖率与 10-26 恰好同值**（29163/34517）：已重跑，不是抄旧数；`coverage-baseline.json` 的
   `measuredAt` 已改为 2026-10-27，报表时间戳 00:20:08。
3. **C07 在 C08 / C13 未闭合时执行**（用户指定顺序）。C08 只动 `docs/adr/**`、C13 只动
   v1 归档横幅 / 四份排期件 / 引用改写，均不在 `verify-facts` 的检查面内；若 C13 之后又改
   `facts.md`、`security-design.md`、`tool-contract.md`，必须重跑 `verify-facts`。
4. **eval 包的 22/158 是 `pnpm eval:unit` 的值**：`pnpm -F @bah/eval test` 因 cwd 在 `packages/eval`
   会丢 `profiles/`（实测 5 例红）。facts.md 已换命令；`packages/eval/vitest.config.ts` 的
   "零 workspace 依赖"注释与现状不符（有 3 个测试 import `@bah/*`），属代码债，不在本包改。
5. **`docs/coverage-baseline.json` 的 `pct` 仍是手写字段**：门禁会校验它等于
   `covered/total` 四舍五入两位，但生成脚本不会自动写这个字段。
6. **`docs/preflight-2026-10-25.md:44` 的「14（目标 16）」保留**：历史时点记录。

## 5. 下一个包开工前必须知道的一件事

**数字只有一个入口：先改 `docs/facts-sources.md`，再改 `facts.md`，最后跑 `npx tsx scripts/verify-facts.ts`。**
直接改 PPT / 视频旁白里的数字而跳过这两步，门禁不会拦（它只扫白名单文档），
但 C11 彩排抽查会以 `facts.md` 为基准，届时会暴露。
另：新增任何 `scripts/verify-*.ts` 都会让 `gates=35` 变成 36，**必须同批改 `facts-sources.md` 与 `facts.md`**。
